# Задание для рефакторинга: Интернет-магазин

## Описание проекта

Этот проект представляет собой простой интернет-магазин, написанный на React с использованием Redux Toolkit. **Код содержит типичные антипаттерны**, которые необходимо исправить.

## Цель задания

Ваша задача - провести рефакторинг кода, улучшив его качество, читаемость и поддерживаемость.

## Изменения:

## 1. Проблема:

    Вся логика приложения в одном файле.

    ## Решение:

    Код из App.jsx разделён на отдельные компоненты (Filter, Header, ProductCard, ProductList, Cart, ...), в которых легче ориентироваться и легче поддерживать.

## 2. Проблема:

    Redux Provider внутри App.jsx.

    ## Решение:

    Redux Provider вынесен из App.jsx в main.jsx (как в документации самого Redux).

## 3. Проблема:

    Симуляция загрузки данных с API и сайдэффекты внутри компонентов.

    ## Решение:

    Симуляция загрузки данных (товары, пользователь) вынесена из компонентов в Redux хранилище. Загрузка через CreateAsyncThunk и вся логика обновления хранилища теперь внутри, без диспатча лишних действий с фронтенда.

4.  ## Проблема:

    Диспатчи типа действия { type: "app/addToCart", payload: product } - хрупко, нет централизованной логики, она раскидана по компонентам, при изменении логики надо менять в разных местах приложения.

    ## Решение:

    Заменил все диспатчи типа { type: "app/addToCart", payload: product } на вызовы Action Creators.

5.  ## Проблема:

    После вынесения логики загрузки в Redux доступно больше статусов загрузки с которыми удобнее работать.

    ## Решение:

    Переписал UI под статусы загрузок данных (загрузка/успешно/ошибка)

6.  ## Проблема:

    После централизации логики загрузки данных в Redux отпала необходимость в некоторых Action Creators которые мы экспортировали наружу.

    ## Решение:

    Убрал неиспользуемые более Action Creators, хранилище стало чище.

7.  ## Проблема:

    В Хранилище есть вычисления, которые нигде не используются (cartItemsCount, cartTotalAmount, cartTotalSum).

    ## Решение:

    Почистил хранилище от лишних данных, хранилище стало чище.

8.  ## Проблема:

    Одно хранилище содержит в себе логику работы с разными сущностями. Много кода, хуже читаемость, сложнее поддерживать (для маленького проекта ок).

    ## Решение:

    Разделил хранилище на 3 слайса для каждой сущности (товар, пользователь, корзина). store.js используется только для сборки слайсов. Легче поддерживать каждый слайс в отдельности, хранилища независимы друг от друга, меньше кода в каждом слайсе.

9.  ## Проблема:

    Компоненты обращаются к хранилищу напрямую, получая нужные данные, хотя в нём уже прописаны селекторы.

    ## Решение:

    Переписал код, компоненты получают нужные данные с использованием селекторов.

10. ## Проблема:

    Некоторая логика вычислений внутри хранилиша повторяется (пересчёт количества товаров при удалении/добавлении в корзину)

    ## Решение:

    Логика пересчета вынесена в отдельный хелпер (DRY).
